# 2. DEFEITO A — a catraca de +10 do "Salvar Perfil" do rodapé (PROVADO)

**Causa raiz:** `footer_actions._persist_profile_async._on_saved` (`src/hefesto_dualsense4unix/app/actions/footer_actions.py:352-368`) atualiza `self._active_profile_name = nome` (:356) e `self._draft_baseline = draft` (:361), mas **nunca reaponta `self.draft`**. O método que existe exatamente para isso — `DraftConfig.with_profile_identity` (`app/draft_config.py:629`) — tem **um único chamador em produção**: `profiles_actions.py:1719`. O rodapé ficou de fora.

O docstring do próprio `with_profile_identity` (draft_config.py:644-647) descreve esse caminho nominalmente como o bug que ele existe para fechar:

> *rodapé "Salvar Perfil" como "MadJack" → `source_name` continuava apontando para o perfil anterior, então o SEGUNDO "Salvar Perfil" com o mesmo "MadJack" caía no ramo "nome novo" de `to_profile` e zerava regra, prioridade e modo do perfil que ela acabara de criar.*

**Mecânica:** com `draft.source_name` velho, o gate `mesmo_perfil` de `to_profile` (draft_config.py:562-564) responde `False` **para sempre**, e então:
- `match = MatchAny()` (:578-582) — o perfil vira catch-all;
- `priority = priority` do chamador (:571-572), e o chamador passa `_prioridade_acima_dos_catch_all()` (footer_actions.py:344-347), que é `max(prioridade dos catch-all) + 10` (profiles_actions.py:1620-1634).

Como o alvo acabou de virar catch-all, ele entra no próprio `max` — **+10 a cada clique**. E `prompt_profile_name` pré-preenche com `_active_profile_name` (gui_dialogs.py:32-40 / footer_actions.py:289-290), que o save anterior já apontou para o alvo: a catraca é de um clique só.

**Reprodução (5 cliques em "Salvar Perfil", sem mudar nada):**
```
source_name inicial: vitoria
clique 1: prio=11  match=any  ← era criteria/steam_app_1599660, prio 80
clique 2: prio=21  match=any
clique 3: prio=31  match=any
clique 4: prio=41  match=any
clique 5: prio=51  match=any
```
191 = 1 (`meu_perfil`) + 19×10. `191 mod 10 == 1` bate com a base `meu_perfil=1`. O `mode` e o `suppress_desktop_emulation: true` sobreviveram porque `mode_dirty`/`suppress_dirty` estavam ligados (:586-591) — exatamente o que está gravado no `sackboy_nativo.json` dela.

**Por que a suíte é verde:** `test_abas01_conflito_entre_abas.py:437` só exercita o rodapé com `nome_no_rodape == perfil ativo` (`mesmo_perfil=True`). `test_perfil_salva_tudo_rascunho.py:275-287` testa `with_profile_identity` isoladamente, **não** que o rodapé o chame. Nenhum teste cobre o segundo save.
